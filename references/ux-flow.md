# UX 流程：ComfyUI 跑通引导 → 用户心智分析 → 弹窗询问确认 → 专业规划 → 才写 UI

> 铁律：**工作流没在 ComfyUI 跑通（用户确认），绝不进入转换流程**；**UI 代码在用户确认 ui_plan 之前一行都不写**。
> Token 免费，不用节约：分析全面、方案完整、不省步骤不省说明。
> AI 是向导：每步讲清「现在在哪 / 要做什么 / 成功长什么样 / 失败怎么办」；不自己探测替代用户确认。

## 0. S-1 前置门：ComfyUI 跑通引导（用户确认为准，不自动探测）

**引导话术（逐条给用户）：**

1. 「在 ComfyUI 里打开这个工作流 JSON（拖进画布或 Load）」
2. 「看画布上有没有**红色节点/缺节点提示**——有就是缺插件或缺模型，按下面的排查表处理」
3. 「点 **Queue Prompt** 跑一次」
4. 「等它出图——出图了就说明工作流本身是好的，我们才开始转 exe」

**AskUserQuestion Q0**：「这个工作流在 ComfyUI 里跑通过了吗？」
- **跑通了** → 继续 §1 心智分析
- **没跑通 / 报错** → 按 **排查树** 引导，解决后回到 Q0 重新确认：
  - 红色缺节点 → 「这是缺插件：用 ComfyUI Manager 搜节点名安装，装完**重启 ComfyUI** 再跑」
  - 报模型文件不存在 → 「这是缺模型：告诉我要哪些文件（报错里有文件名），放到 models 对应子目录，或指给我已有位置」
  - 采样/参数报错 → 「把报错文字发我，我逐条解读」
  - 显存不足 → 「先用更低分辨率/步数跑通一次再说，分辨率后面 exe 里可以随便调」
- **ComfyUI 都没装** → 引导装 ComfyUI 桌面版是前置任务，范围外但给官方指引
- **原则**：转出来的 exe 复刻的是一个**已被验证能出图**的工作流；带病转换 = 白干。

## 1. 标准意图句式

用户的需求通常是一句话：「这个工作流我只输入文字，你输出图片」「我换参考图出图」。
解析出：**输入面**（用户声明要动的）+ **输出面**（产物形态）→ 其余一切参数内部默认。
exe 界面 = 输入面（核心区）+ 输出面（预览/打开文件夹）+ 显存通用区（自动），不添加用户没要的东西。

## 2. S1A 用户心智分析（AI 自查 + 用户验证）

1. **用户是谁**：个人创作者/批量生产/调试参数党？→ 决定默认值策略与信息密度
2. **心动线**：打开程序第一眼找什么 → 第二眼 → 点生成。信息层级复刻这条线
3. **哪个参数在惩罚用户**：显存（爆显存/反复重载）、加载时长（大模型/LLM）→ 显性化 + 自动化
4. **状态恢复**：上次选择全回来（默认）

## 3. S1B 弹窗询问（S0 之后；前置门见 §0；AskUserQuestion，以工作流节点 id 为锚）

**第一步：先在回复里列出完整「节点 id → 字段 → 类型 → 现值摘要」候选表**（从 S0 graph_report 全量枚举 widget 输入，按语义分组标注推荐），让用户看到全部可选项；**第二步**再弹 AskUserQuestion。

**只问两题，都给推荐项；用户未响应 → 声明「按推荐执行，随时可改」再动手。**

- **Q1（multiSelect）保留哪些输入**：候选 = 上表分组（提示词类/尺寸类/数量种子/模型选择类…），用户可多选推荐组、也可在回复里**直接补写表上任意 node id**。
- **Q2（single）分支落地确认**：工作流有 N 条路径（path_map），按「多分支=多 exe」原则：
  - 拆成 N 个 exe（每个只含自己路径参数，无模式切换）【推荐】
  - 或只生成其中某一条路径的 exe
- **未选中参数的处理（用户原则）**：**默认全部不渲染**——UI 只出现用户选中的输入；其余用工作流原值。不再设「高级折叠区」。
- **不问的**：显存（全自动，见 §4）、主题（默认深色 Fluent 蓝）、输出命名（前缀+时间戳）、路径（自动探测）——有异议用户会自己说。

## 4. S1C 专业 UX 规划（AI 产出，随 ui_plan 给用户过目）

- **布局**：按 ui-style.md §3 图像输出型双列模板（左输入 470px / 右大预览 430px+ / 底部运行条）——硬规格，禁止压缩输入区
- **参数行卡**：label 110px + 控件弹性；同类合并行；主输入区 ≥150px
- **状态清单**：每控件五态（默认/hover/禁用/加载中/错误），禁用带原因
- **反馈文案**：提交→步进（节点中文名）→ 成功（InfoBar+大预览自动更新）/ 失败（InfoBar error + 建议动作）
- **可达性**：全键盘可达，focus 环可见，对比度 ≥4.5:1

## 5. 显存通用功能（自动适配，不询问）

- 运行条常驻「**完成后释放显存**」勾选（勾=跑完卸载+清缓存；不勾=常驻连出快）
- **[立即释放显存]** 独立按钮（`CMD release_vram` → 只卸载权重不清缓存）
- 显存空闲 MB 常驻状态行；bootstrap 自动 lowvram / disable_async_offload（坑25/30）
- 图内卸载类节点执行期按勾选状态覆写（不双清不漏清）

## 6. S1D 契约落地

确认后更新 params_schema（含 ui_plan 决议与节点绑定）→ 生成 UI（qfluentwidgets，参照 reference_ui_moss.py）→ 启动冒烟 → 截图/窗口给用户验收 → 交付。

## 7. 禁止事项

- 禁止跳过弹窗询问直接生成 UI（未响应也要先声明按推荐执行）
- 禁止在单个 exe 里做流程分支切换 UI（多分支=多 exe）
- 禁止把显存功能藏进高级区或做成晦涩术语（「一次/连续」→「完成后释放显存」）
- 禁止互斥概念用多选、可叠加概念用单选
- 禁止 alert()/confirm() 原生弹窗（用 InfoBar/ContentDialog）
